# Feature: 글로벌 경제 브리핑 및 실시간 알림

## 1. 개요 (Overview)
글로벌 거시경제, 주요 기업 정보, 지정학적 리스크(전쟁 등) 등 주식 시장에 큰 영향을 미치는 주요 정보들을 수집하여, **개장 전 모닝 요약 브리핑**과 **장중 실시간 알림** 형태로 제공하는 기능입니다. 
데이터 신뢰도를 높이고 중복 데이터 처리에 따른 AI API 비용(Token) 낭비를 원천 차단하기 위해, **글로벌 경제 매체 Axios(액시오스)의 주요 RSS(Macro, Business, Tech 등)를 단일 데이터 출처로 사용**합니다. 영문 기사 기반의 심도 있는 인사이트를 AI를 통해 한국어로 요약하여 전달합니다.

## 2. 수집 및 분석 파이프라인 (2-Step AI Pipeline)

효율적인 비용 관리와 정확한 요약을 위해 수집 및 분석을 2단계로 분리합니다.

### 데이터 수집 대상 및 스펙 (Data Source Specification)
- **타겟 피드 (Axios RSS):** 주식 시장에 가장 직접적인 영향을 주는 글로벌 매크로 및 빅테크 관련 3개 카테고리만 수집합니다.
  - Economy & Business: `https://www.axios.com/economy-business/feed.rss`
  - Technology: `https://www.axios.com/technology/feed.rss`
  - World: `https://www.axios.com/world/feed.rss`
- **추출 필드:** `title` (제목), `link` (원문 고유 식별자), `pubDate` (발행 일시), `description` 또는 `contentSnippet` (Axios 특유의 Smart Brevity 요약본)
- **중복 방지 로직 (무결점 DB 캐싱):** 
  - 스케줄러가 수집한 RSS 기사 목록 전체를 DB에 일괄 `INSERT` 하되, `link` 고유키 충돌 시 무시(`ON CONFLICT DO NOTHING`)하는 방식으로 중복을 1차 차단합니다.
  - 이를 통해 RSS 순서 역전이나 지연 발생 시에도 데이터 누락을 완벽히 방지합니다.

### Step 1: 1차 제목 필터링 (저가/경량화 모델 사용)
- **트리거:** RSS 피드 업데이트 시 스케줄러에 의해 동작 (새로 INSERT 성공한 기사들만 대상).
- **방식:** Axios 영문 기사의 **'제목(Title)'**만을 경량화 모델에 전달하여 3단계 상태로 분류.
- **판단 기준 및 출력 상태 (`status`):**
  - `"Pass"` (관련됨): 주요 거시경제 지표, 유명 빅테크 등 경제적 영향이 명백한 기사.
  - `"Drop"` (제외): 정치 스캔들, 단순 행사 등 주식 시장과 전혀 무관한 '완전한 비경제글'. **(주의: 토큰 낭비 무한 루프를 막기 위해 기사를 삭제하지 않고 `status`만 'Drop'으로 업데이트하여 DB에 메타데이터를 유지함)**
  - `"Hold"` (보류): 모델이 잘 모르는 신규 상장 기업이거나 문맥이 애매한 경우. (보수적 접근)
- **출력 (JSON 스키마 예시):**
  ```json
  {
    "status": "Hold",             // 'Pass', 'Hold', 'Drop' 중 택 1
    "reason": "신규 상장 기업으로 추정되어 추가 확인 필요", // 판단 사유 (오분류 방지용)
    "category": "거시경제",       // '기업', '섹터', '거시경제', '지정학', '기타'
    "targetKeywords": ["Reddit", "IPO"] 
  }
  ```

### Step 2: 2차 본문 요약 및 심층 분석 (고성능 모델 사용)
- **트리거:** 1차 필터링 결과가 `"Pass"` 이거나 `"Hold"` 인 기사에 대해 동작.
- **방식:** 기사의 원문 링크(또는 RSS의 Description)를 참조하여 고성능 AI 모델로 심층 분석 수행.
- **처리 로직:**
  1. **Hold 재평가:** 1차에서 `"Hold"`로 넘어온 기사의 본문을 읽고, 최종적으로 경제적 가치가 없다고 판단되면 여기서 최종 `"Drop"` 처리.
  2. **요약 및 평가:** 최종적으로 관련성이 있는 기사들에 한해, 자연스러운 **한국어로 3~4줄 핵심 인사이트 요약**을 진행.
  3. **지표 산출:** 시장에 미치는 **중요도(Importance, 1~10점)**와 해당 이슈가 시장에 미칠 **투자 방향성/센티먼트(Sentiment: 호재/악재/중립)**를 함께 도출.
- **최종 저장 데이터:** 상태(Pass), 한국어 요약본, 카테고리, 중요도(1~10), 센티먼트(호재/악재/중립), 추출 키워드 등.

## 3. 알림 발송 정책 (텔레그램 연동)

전달받을 메인 플랫폼은 **텔레그램(Telegram)**으로 하며, 알림 스케줄은 다음과 같이 구성합니다.

### A. 모닝 브리핑 (Morning Summary)
- **발송 시간:** 매일 오전 7시 30분.
- **대상 데이터:** 전날 장 마감(또는 오후)부터 발송 시점까지 1차 필터링을 통과 및 2차 요약이 완료된 모든 기사.
- **형태:** 밤사이 발생한 이슈들을 카테고리별(거시경제, 기업 이슈 등)로 묶어 하나의 긴 요약 메시지로 텔레그램 발송.

### B. 장중 실시간 알림 (Real-time Alert)
- **활성화 시간:** 한국 주식시장 개장 및 장중 시간 (예: 08:30 ~ 15:30).
- **대상 데이터:** 해당 시간대에 새로 수집되어 1차 필터링을 통과한 기사.
- **형태:** 기사 수집 및 요약이 완료되는 즉시 텔레그램 단건 메시지로 실시간 발송하여 즉각적인 시장 대응 지원.

## 4. 웹 UI 요구사항 (Web Dashboard)
- **모닝 브리핑 이력 뷰:** 과거 날짜별로 발송되었던 오전 7:30 브리핑 내용을 확인할 수 있는 아카이브 페이지.
- **실시간 속보 타임라인:** 장중 발생하는 실시간 알림 내역을 메인 피드와 별개로(혹은 통합하여) 볼 수 있는 전용 위젯 또는 피드 탭.
- **텔레그램 연동 관리:** 사용자가 자신의 텔레그램 봇 토큰/Chat ID를 등록하거나 구독을 켜고 끌 수 있는 설정 페이지.

## 5. 영향 받는 시스템 요소 (향후 반영 필요)
- **DB 스키마 (`00_base_data-modeling.md`):** 
  - `global_news` (또는 `briefing_feed`) 테이블 추가 (제목, 요약본, 원문링크, 카테고리, 발행일 등)
  - `user_settings` 에 텔레그램 연동 정보 컬럼 추가
- **스케줄러 (`03_flow_cron-scheduler.md`): 주야간 차등 폴링(Polling) 전략 적용**
  - **야간/미장 시간 (예: 15:30 ~ 07:00):** 데이터 유실 방지 및 API/서버 비용 최소화를 위해 여유롭게 **2시간 주기**로 RSS를 수집하여 DB에 적재. (알림 발송 없음, 오전 7:30 브리핑 발송용 데이터 수집)
  - **국장 시간 (예: 08:30 ~ 15:30):** 시장의 즉각적인 대응을 위해 최대한 짧은 **1~3분 주기**로 초실시간 폴링 수행. (새로운 데이터 발견 시 즉시 단건 알림 발송)
